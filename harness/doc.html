The composition of pages

A page is a fragmentainer: a box that holds one fragment of a flow and gives back the place where it had to stop. The browser lays out one long column without effort, and a paginator asks it, again and again, where the column would end if it were only so tall. The answer is a position, and the next page begins there.

ProseMirror keeps the document as a tree of nodes and counts its positions in tokens, so a position is a single integer that survives every edit through a Mapping. That integer is the break token the Layout API never shipped. When a step inserts three characters before a cut, the cut moves by three, and nobody needs to look at the DOM to learn it.

What the view has to do

The view draws the state, reads the reader's keys, and answers questions of geometry. Everything else belongs to the plugins, which never touch the DOM: the keymap turns a key into a command, the history remembers steps, and the input rules watch the text as it is typed.

  • Render the document into fragments, each filled from where the last one stopped.

    • A fragment holds a slice, and a slice keeps its open ancestors.

      • A list item cut across two pages is still a list item on the second one.

      • Its numbering reads from the source, not from the page.

    • The positions of every rendered node are recorded as they are written.

  • Draw the selection with the browser's own, inside the fragment that holds it.

  • Apply every key to the model first, and render after.

An example

The default fragmentainer measures its own overflow. Its whole interface fits in a few lines:

const box = new OverflowBox({ width: 480, height: 640 });
const { to } = await box.fill(doc, from, renderSlice);
if (to != null) next.fill(doc, to, renderSlice);

The browser fills, the engine reads. A rich fragmentainer is the overflow box plus judgement: it starts from the overflow and walks back to the best place to cut.

A figure travels with its text: and the line wraps around it as any inline content does, so the cut can fall before or after it but never through it.

Where it goes next

Two boxes of fixed height come next: the chain held in plugin state, an edit mapping both entries, and only the touched fragment filled again. After that the slice renderer learns the shallow siblings, and then a real page takes the place of the box, with margin boxes, named pages and the make-up order behind the same single answer: the position where it stopped.
