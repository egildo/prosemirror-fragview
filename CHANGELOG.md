# Changelog

## Unreleased

- A host can give the pages its own serializer. The `domSerializer` prop, direct or from a plugin, is a `DOMSerializer` whose node and mark specs the slice renderer writes with, as `clipboardSerializer` is for `EditorView`'s copy; a host used to patch `schema.cached.domSerializer` to resolve its images' `src`. `sliceRenderer(words, faces, domSerializer)` takes it as a third argument, and a new value through `setProps` invalidates the chain. `setProps` also rebuilt the renderer from the new props alone, so a call that gave only `domSerializer` or `words` dropped the other's earlier value; it reads the merged props now. The case is `a domSerializer prop writes the pages with the host's node specs` in `test/slice-renderer.test.js`.
- The fragments plugin's state serializes. It had no `toJSON` or `fromJSON`, so a state reopened from JSON started a new chain of one dirty entry, and a paginator keyed by the entries' keys found no entry for its rows and dropped them. The state is `{ entries }` as it is, when the plugin is named in `EditorState`'s `pluginFields`. The case is `a state reopened from JSON keeps its chain` in `test/fragments-plugin.test.js`.
- `nodeDOM` for a node that opens at a cut inside another that opens there was suspected to answer null, since it compared the position to the outermost node opening at the cut. Not reproduced: a section opening at a cut with its first paragraph (`test/atoms.test.js`, `nodeDOM of a node that opens at a cut inside another`) answers both elements, the pointer falling back to the fragment before. The case stays as a guard.
- The view's element has a role and can have an accessible name. The `attributes` prop, direct or from a plugin, an object or a function of the state, reaches `view.dom` as `EditorView`'s does: classes and styles add up after the view's own, for any other name the first to give it wins, an attribute a prop stops giving is removed at the next state or `setProps`, and `contenteditable`, `translate` and the writer opt-outs cannot be overridden. Without a `role` from any prop the root is `role="textbox"` with `aria-multiline="true"`; it used to carry no role and no name, and the prop was ignored. The fragments are still rebuilt at every fill, and what a screen reader makes of that waits for a measurement, made when a host asks (the ruling of 2026-11-08).
- Home and End move the caret to the start and the end of its visible line, and Shift+Home and Shift+End extend the selection there. Chromium on macOS scrolled the window on these keys and left the caret where it was, in any contenteditable; the paged layout is the view's, so the view now takes the keys (ruled 2026-11-08). The line is read from its rects in the caret's page, and an end of line stays on its line and on its page, before the space it wraps at or the cut. With Cmd, Ctrl or Alt the keys are left to the browser, and a node selection stands.

## 0.1.3 (2026-11-08)

- A face offered a new node after a fill is asked `update` with `getPos()` answering the position it is offered, as the constructor is, and as `prosemirror-view` answers inside `update`. It answered `undefined` there, since the face was still parked. A view that lays out its inside by it read wrong positions: `prosemirror-spreads`' table numbered every cell from −1, so landing a cell's value closed its buffer, removed the focused input and focused no cell, and the focus fell to the body.

## 0.1.2 (2026-11-08)

Fixes from the assessment of 2026-11-07.

- An edit that moves a cut no longer refills the whole rest of the document before the browser paints again. The ripple fills the first entry, the head's and the ones before it, and every entry whose fragment before it starts above the foot of the viewport (the window's, clipped by each scrolling ancestor), so the pages in view and one more; the rest is filled in idle slices of 10 ms, each taken within 50 ms when the browser offers no idle time (with the root focused, measured in the harness, no idle callback came in 3 s), and an input ends the slice it falls in. Measured on 400 paragraphs in 500 × 400 boxes (100 pages, `test/ripple.test.js`), an Enter at the end of the first paragraph: before, all 100 fills ran before the next frame, which came 226 to 258 ms after the keystroke; after, 4 fills before the next task and before the next frame, which comes 17 to 20 ms after the keystroke, and the chain settles 830 to 860 ms after it, equal to a fresh fill. The view's new `rippling` is true while a slice is awaited, so a reads loop that finds a dirty entry and no fill in flight tells a paused ripple from one stopped short (`prosemirror-beltype`'s `Chain.check` should read it); parked faces are not swept while it is. A construction or an `invalidate()` fills the same way: the first screen and one more, then the rest in slices.
- A whole element written into a page from outside the model is drawn over too. `execCommand('insertHTML')`, a text expander inserting a span, or an extension removing a block used to stay on screen while the model did not hold it, silently, and was lost at the next save; only text writes were drawn over. Now an element that no render drew, added into an element a render drew, or an element a render drew taken away, outside a fill of that page, dirties the page, which is drawn again from the model, under the same budget and single warning as text writes. A container's own elements, such as a page's chrome, are not taken for such a write. A write inside a shadow root is still not observed and stays.
- A page whose content changes height after its fill (an image that arrives at its top) now cuts the page before it again as well as itself. Its cut may have read that content, and only the page itself used to be refilled, so a cut that should move back stayed; an engine that restarts one page earlier is now matched.
- A fill may answer `shows: { from, to }`, the positions its fragment shows outside its own range, as a page after a cut through a table row shows the rest of an earlier cell, whose positions lie inside the page before. The entry keeps it, mapped as `from` and `to` are, and a change there dirties the fragment: a same-length replacement or a mark in such a remainder used to refill only the page before, whose cut and hint stayed the same, so the page that shows the text kept the old text. `indexAt`, and the caret drawn through it, gives such a position to the fragment that shows it when the one that owns it by range is built and its `pointAt` answers null. `refilled(tr, key, to, reach, shows)` carries it. A fill that answers none behaves as before.
- A plugin's DOM events, clicks and paste transforms reach it. The view listens to every event a `handleDOMEvents` names, in the direct props or in any plugin's, a plugin added after construction or a prop given to `setProps` included; `focus` runs its handler and `blur` has a listener. It used to listen only to the events it answers itself. A click asks `handleClickOn` and `handleClick` at the release, a double or triple click asks `handleDoubleClickOn` and `handleDoubleClick`, or the triple forms, at the press, as in `prosemirror-view`. A paste applies `transformPastedHTML`, `transformPastedText` and `transformPasted`, and a clipboard holding only a file (a pasted image) reaches `handlePaste` with an empty slice, where it used to be swallowed.
- A selected image, rule or embed shows that it is selected: every shown piece of a node selection's node carries `ProseMirror-selectednode`, a block divided across pages on each page that shows it, as `prosemirror-view` marks it. Measuring copies are never marked. A leaf with a node view is still marked by its face. A node decoration's `class` goes on its node's pieces the same way, where node decorations used to be ignored. The selection paints each of its `ranges`, so a cell selection paints its cells, and a selection that is not `visible` paints nothing. The slice renderer records each node element's depth in `DEPTHS` for this.
- A fragmentainer is handed its hint on every fill, as `fill(doc, from, render, hint)`, not only through the factory when it is built. A page refilled after the page before it answered another hint used to cut under the old one, unless it asked for the new one itself, as `prosemirror-beltype`'s `Chain.hintFor` does.
- A schema that mixes structured and ordinary marks throws a `RangeError` naming both kinds, from the view's constructor and from the first render. Its ordinary marks used to vanish from the pages without a word. A test now fails if `prosemirror-model`'s `serializeFragment` stops calling `serializeNodeInner` and `serializeMark`, the two methods the slice renderer replaces, so a release that renames them shows up in this suite and not as an empty position map.
- A fill that rejects no longer stops every page after it without a word to the host. A `handleFillRejected` prop, `(view, error, container, from)`, may answer with a fill result, or a promise of one, that stands for the rejected fill, and the chain goes on from there. Unanswered, the error is raised apart as before and the entry stays dirty, so the next update fills it again. The fragmentainer's contract no longer promises that a fill writes its DOM before its first wait: one that writes after a wait is painted when its answer arrives, as a page an engine cuts always was.
- A later page renumbers after an edit an earlier page absorbs. An item inserted or removed before a cut in a list left the next page's `value` and away siblings as they were, so its numbers and its `:nth-child` and `+` selectors read stale on screen while print was right. A step that inserts or removes a child of one of an entry's divided ancestors before the one it opens in now dirties the entry. The document's own children are left out, since counting them would refill every later page on every new paragraph.
- A refused node view arriving with a new state throws before the view takes the state. A host that registers such a plugin at runtime (Tiptap's `registerPlugin`) used to leave the view holding a state its DOM never drew. `setProps` with a refused `nodeViews` keeps the old props the same way.
- A selection read back from a page not yet refilled, or an input's target range there, no longer resolves a position past the document's end: it is passed over, as `posAtCoords` and `leafAround` already passed it.
- The view answers `root`, `_root`, `props`, `isDestroyed` and `dragging` as `EditorView` does, so a plugin that reads them at construction (`prosemirror-tables`) no longer throws. `root` is the document or shadow root the view lives in, and `hasFocus()` and the selection's stand-down ask it, so a view inside a shadow root sees its focus. `dragging` is always null. `root` does not patch `getSelection` onto a shadow root's prototype as `prosemirror-view` does.

A clean checkout passes its tests. Vite's dependency optimizer is off for the harness and the suites, since every dependency here is an ES module; with it on, parallel suite files fought over one cache and 57 to 61 of 157 tests failed on the first run. `FRAGVIEW_VITE_CACHE` goes with it.

The harness stands on its own.

- The generic schema the harness and the phase 3 scripts parse with is now `harness/schema-generic.js`, copied from the old studio. `BELTYPE_STUDIO` is gone, so a clean clone runs every script. The file is exported as `prosemirror-fragview/schema-generic` for `prosemirror-beltype`'s measurement. It is no part of the view's API.

Browser scope, by the ruling of 2026-11-07.

- The README says which browsers are verified: editing, selection and composition in Chromium only. Elsewhere the view loads and works as an editor, unverified. Android is unsupported for now, and a host there should mount a plain `EditorView`.
- A Backspace or Delete whose `beforeinput` carries no target range now deletes one step: the character beside the caret, a surrogate pair whole, an inline node, or the selection. It used to delete nothing, silently. Chromium always sends the range; a synthetic event and, unmeasured, other browsers may not. A caret at a textblock's edge still deletes nothing, and the join stays the keymap's.

Leaf node views, by the ruling of 2026-11-07.

- A `nodeViews` prop in `prosemirror-view`'s shape, for leaf node types only. The host's element is shown once, in the page that holds the node, and keeps its state across refills and across a move to another page, by `moveBefore`. `update`, `destroy`, `selectNode`, `deselectNode`, `stopEvent`, `ignoreMutation` and `getPos` hold their meanings.
- A node view for a block or for text throws a `RangeError` at the prop. A plugin that registers one for a block, as `prosemirror-tables`' `columnResizing` does for `table`, now gets that refusal, where its view used to be ignored. A `markViews` prop warns once.
- A leaf with a node view is drawn in every copy as a stand-in: a wrapper around `toDOM`'s element, `display: block` or `display: inline`, marked `data-fragview-face`. `toDOM` stays what prints. `nodeDOM` answers the wrapper. A selector on the leaf's siblings sees the wrapper in the leaf's place.
- `sliceRenderer(words, faces)` takes a second, optional argument, and `FACE_STAMP` is exported.

Block node views, by the ruling of 2026-11-08: the face follows the cut, and the cut never follows the face.

- A block whose node view has no `contentDOM` is admitted, which replaces the refusal of a block above; text is still refused at the prop. A view that answers a `contentDOM` is refused when it is made, now saying that a fragmented view gives a node view only to a node drawn whole, since a content hole would be divided across fragments, and the node keeps its drawing. A plugin's table view over the whole table, as `prosemirror-spreads` has, now runs.
- A block's stand-in is the `display: block` wrapper around the whole `toDOM` drawing, rows and cells mapped as without the wrapper, so a fragmentainer cuts it as it cuts the bare drawing, and the `fragment` word goes on the drawing. Nothing is pinned on a block: measured 2026-11-08 under a real paged-media engine, a table's height is a minimum, and a pinned table that is divided stretches the row before the cut past the page's foot.
- A face is placed only where its node stands whole in one fragment, its wrapper's mapped start and end the node's, and where no earlier built fragment shows the node's start, so a node has at most one face, leaves included: a leaf a page engine shows whole on two pages used to have its constructor run twice and a live element on both. A piece that fails keeps `toDOM`'s drawing, and the node is warned once on the console, `prosemirror-fragview: the "<type>" at <pos> stands in more than one fragment, so it is drawn from toDOM in each; its node view is placed only where it stands whole in one.` A wrapper that holds its face carries `data-fragview-face="placed"`, so a host reads `nodeDOM(pos)` to know. A face standing in a later fragment gives itself up to an earlier one that comes to hold its node whole, and that wrapper gets its drawing back.
- A block face drawn at another box than `toDOM`'s is warned once per type, `prosemirror-fragview: the node view for "<type>" draws <w> by <h> where toDOM draws <w> by <h>; a block is cut at its drawing's size, so its view should draw at that size.`, and kept; nothing is filled again for it, at placement or when it resizes.
- `getPos()` answers the node's position inside the constructor, where it used to answer `undefined` until the element had a wrapper. The constructor's fourth argument is the node decorations whose range is exactly the node's, where it was always empty, and after a paint that changes them a placed face gets `update(node, decorations)`; false, or no `update` on a block, destroys it and makes another in its wrapper. An update for a new node is given them too.
- The inside of a placed block face is the face's, as `prosemirror-view` treats a node view without `contentDOM`. A position inside resolves to the wrapper's edge in `domAtPos` and `coordsAtPos`, and `nodeDOM` answers null for it; `posAtCoords` over the face answers the node's position for both `pos` and `inside`; a model selection with both ends inside writes no browser selection and is handed to the face's `setSelection(anchor, head, root)`, relative to the node's start, once per change; a browser selection inside the face is not read back; nothing inside is marked `ProseMirror-selectednode` or with a node decoration's class, while a divided block's pieces are still marked; and the arrows step over a placed face as over an atom. `leafAround` is now `faceAround`, which answers a placed face as it answers a leaf.

A delete at a block's edge.

- A caret at the edge of its textblock no longer deletes across the boundary. Backspace at the start of an `isolating` node (a table cell) poured it into the one before: the view applied the browser's target range, and `tr.delete` joins across any boundary. Now, as `prosemirror-view`'s `stopNativeHorizontalDelete` has it, Backspace and Delete at a textblock's edge are the commands' alone (`joinBackward`, `joinForward`), which honour `isolating`; without them nothing joins.

Fixes from the integration review of 2026-11-04.

- A `ReplaceAroundStep` (`setNodeMarkup`, a wrap, a lift) now dirties every fragment it covers. It used to dirty only the fragments holding its two tokens, so the middle of a list or section of three or more pages kept its old markup.
- A key on a view that is not editable no longer reaches the keymaps, as in `prosemirror-view`.
- A `dirtied` or `redraw` that arrives while the fragment is filling is no longer lost. The fragment is filled again after the fill in flight. Entries carry a new `asked` count.
- A fill may answer `reach`, the last position its decision read, and a change up to there dirties the fragment. Without it the first word after the cut stands for it, as before.
- A text node changed, added or removed under a fragment outside a composition now dirties that fragment, which is drawn again from the model. Three such redraws per entry and per document, then one warning.
- The root carries `translate="no"` and the opt-out attributes of Grammarly and LanguageTool. A host removes one from `view.dom` to allow that writer.
- A `compositionend` taken by a handler still redraws its fragment from the model.
- A refill that keeps its `to` but changes its hint now fills the next fragment, which was cut under the old hint. Hints are compared by their JSON.
- A clean clone installs and tests: the private studio is no longer a dev dependency. `BELTYPE_STUDIO` names its checkout for the harness's `schema=generic` mode.
- `LICENSE` carries the notice of `prosemirror-view`, for the code ported from it.
- `hasFocus()` answers whether the root itself has focus, as in `prosemirror-view`. `hasFocus()` used to be true for anything focused inside the root. The view has its own test, `ownsSelection()`: it neither reads nor writes the browser's selection while focus is on a form control or inside a leaf's drawing, so such an element keeps its focus. A focusable element that holds the document's text (a mark or a block with a `tabindex`) is still the view's, and a click in it moves the selection.
- An event from a form control (`input`, `textarea`, `select`, `button`, or anything inside one) or from an editing host nested in a leaf's drawing belongs to that element: neither `handleDOMEvents` nor the view's handlers see it. Any other element with input of its own stops propagation at its own root. A plain `toDOM` `<input>` can now be typed in. It used to lose every key, and Backspace ran the keymaps against the document.
- A click or a drag that the view answers brings the focus back to the root from anything focusable the press landed on (a link, a `tabindex`), and the root taking focus back from such a control or leaf draws the model's selection, as a `focus` handler does in `prosemirror-view`. The old `hasFocus()` did the first by accident.
- A text node changed inside a leaf's own drawing is no longer a foreign write, so a custom element in a leaf can render text without refilling its page. Foreign writes to the document's text are caught as before, in a fragment not yet refilled too: the walk and `posAtCoords` no longer throw on a position past the document's end.
- `view.docView` is truthy until `destroy()` and null after, for `y-prosemirror`'s cursor plugin, which reads it to ask whether the view is alive.
