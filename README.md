# prosemirror-fragview

A fragmented view for ProseMirror. `FragmentedView` holds an ordinary `EditorState`, speaks the same protocol to the same plugins as `prosemirror-view`'s `EditorView`, and renders the document into a chain of FRAGMENTAINERS: components that pull content from a position and give back the position where they had to stop. The basic fragmentainer, `OverflowBox`, reports the browser's own overflow. A paginator's page is a fragmentainer that reports the best cut under its own rules, with every paged-media feature behind it, and still, in the end, a position.

The design and its phases are in [docs/plan.md](docs/plan.md).

Phases 1 and 2 are built. Phase 1 is the package, and the proof that a `FragmentedView` with one infinite `OverflowBox` behaves as an `EditorView`: 18 of 19 parity acts equal on document, selection, undo and redo, the nineteenth showing `EditorView` reading a stale selection under keys pressed back to back. Phase 2 is fixed-height boxes and the chain. The chain is held in plugin state and mapped through every transaction, and only dirty fragments are refilled, in order: one character typed refills one box and dirties none, a new line near the top ripples through all five boxes of the harness document, and undo restores the chain. A fragment the edit did not touch keeps its DOM, so a key costs about a box's worth of work whatever the document's length. The selection is painted across fragments as one highlight, geometry answers across the chain, a box shorter than its first line still takes it, a `near` window policy builds only the boxes around the viewport, and `moved` refills from late truth. What was built, the numbers and what is not done yet are in [docs/results.md](docs/results.md); `npm test`, `npm run parity` and `npm run chain` run it again. Written with BelType's studio as the venue; the first paginator to implement the fragmentainer is BelType's Cicero.
